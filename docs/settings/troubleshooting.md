# 14. カメラ・校正の異常時の対処

## 症状別の対処

### 「カメラ① のシリアル番号が未設定です」

- 原因: `cam_id.yaml` が `null` のまま
- 対処: 設備設定 → カメラ設定 → シリアル番号を設定 → 保存

### 「カメラ① (シリアル XXXXX) を開けませんでした」

- 原因: カメラ未接続 / 電源 OFF / 他アプリが使用中 / シリアル誤り
- 対処:
  1. ケーブル・電源を確認
  2. 他のソフト（IC Capture 等）を終了
  3. 「カメラ検索 / 更新」でシリアルを再確認
  4. 「接続テスト」で切り分け

### 「カメラ① は検査で使用中です」

- 原因: 別スレッドがカメラを所有している
- 対処: メイン画面へ戻り、検査を停止してから操作する。
  1 台のカメラを同時に 2 つの画面が使うことはできません（意図的な安全装置）。

### 「ホモグラフィが未計算です。校正を実行してください。」

- 原因: `homography_param_cam1.yaml` / `cam2.yaml` が `null`
- 対処: カメラマージ画面でホモグラフィを計算する（[calibration.md](calibration.md)）

### 校正ファイルが壊れた / 誤って削除した

```bat
python tools\machine_config_backup.py status
python tools\machine_config_backup.py verify
tools\restore_machine_config.cmd
```

### 「不適合: カメラ① の解像度/向きが校正時と異なります」

- 原因: 校正後に解像度・180°回転・シリアルを変更した
- 対処: 再校正する（[calibration.md](calibration.md)）

### 「旧形式のカメラ番号で設定されています」

- 原因: `cam_id.yaml` が `0: 0` のようなインデックス指定
- 対処: カメラ設定でシリアル番号を設定し直す（動作は継続します）

### プレースホルダ（カメラ未接続）の映像が表示される

- これは**開発用の代替映像**です。生産用の画像としては扱われません。
- この状態では生産検査は実行されません。
- 実機を接続し、シリアル番号を設定してください。

## ログの確認

| ファイル | 内容 |
|----------|------|
| `aikensa/logs/crash.log` | 起動・例外・Qt メッセージ |

起動時に以下が記録されます。

```
===== APP START 2026-11-20T15:00:00 =====
```

検索のヒント:

```bat
findstr /I "camera ホモグラフィ 校正" aikensa\logs\crash.log
```

## 設定画面が開かない

1. 「設備設定」ボタンはメイン画面の上部にあります（黄色）。
2. 開かない場合は `aikensa/logs/crash.log` を確認してください。
3. `.ui` ファイルの破損が疑われる場合は、自動テストで検証できます。

```bat
python -m pytest tests\test_settings_ui.py -v
```

## それでも解決しない場合

以下を添えてエンジニアへ連絡してください。

1. `aikensa/logs/crash.log`
2. `python tools\machine_config_backup.py status` の出力
3. 設備設定画面のスクリーンショット（状態表示部分）
4. 実施した操作の手順
