# 8. 設定の保存と復元 / 9. 状態の意味 / 11. バックアップからの復元

## 保存の仕組み（安全性）

設定は「検証 → 一時ファイル書き込み → 置換」の順で保存されます。

1. 入力値を検証（範囲・重複・形式）
2. 問題があれば**保存しない**（画面に日本語でエラー表示）
3. 同一フォルダに一時ファイルを作成
4. ディスクへ書き出し（fsync）
5. 一時ファイルを本来のファイル名へ**不可分に置換**

このため、停電や強制終了が発生しても「中途半端に書けた校正ファイル」は残りません。

### 複数ファイルをまとめて変更する場合

全体微調整と品番別調整は「版（リビジョン）」単位で扱われます。

1. `aikensa/core/param/adjustments/revisions/<版ID>/` に候補ファイルを退避
2. すべてのファイルの SHA-256 を検証
3. **すべて問題なければ**本番ファイルを置換
4. 途中で失敗した場合は、置換済みのファイルを元に戻す

部分的にだけ新しい設定が適用される状態にはなりません。

## 状態の意味

| 状態 | 意味 | 検査への影響 |
|------|------|--------------|
| 未作成 | ファイルが存在しない | 生産検査は開始されません |
| 未設定 | ファイルはあるが `null` | 生産検査は開始されません |
| 不正 | 内容が壊れている / 検証エラー | 生産検査は開始されません |
| 不適合 | カメラ設定（解像度・向き・シリアル）が校正時と違う | 再校正が必要 |
| 準備完了 | 正常に読み込めた | 生産検査が可能 |

カメラが 1 台でも「準備完了」でない場合、アプリは生産検査を実行しません。
プレースホルダ映像（「カメラ未接続」）は**絶対に生産用の画像として扱いません**。

## 再起動後の動作

- 保存済みの値がそのまま復元されます。
- 適用中のリビジョンも復元されます。
- 壊れた設定は読み込み時に「不正」として拒否され、アプリは起動します。
  直前の正常なリビジョンは残っているため、そこから戻せます。
- 不完全な校正が自動的に有効化されることはありません。

## 設定履歴

「設備設定」→ **設定履歴** で以下を確認できます。

- 版ID、日時、作業者、端末ID、変更内容
- 適用中の版
- 「選択した版に戻す」でロールバック
- 「バックアップ作成」でバックアップを取得

履歴は `aikensa/core/param/adjustments/revisions/` に保存されます（Git 管理外）。

## バックアップからの復元

### コマンドで行う場合

```bat
:: 1. バックアップの検証（省略可。restore は自動で検証します）
tools\verify_machine_config_backup.cmd

:: 2. 復元（内容の確認 → Y で実行）
tools\restore_machine_config.cmd
```

Linux:

```bash
tools/verify_machine_config_backup.sh
tools/restore_machine_config.sh --dry-run   # 何が戻るか確認
tools/restore_machine_config.sh
```

### 画面から行う場合

「設備設定」→ **校正・位置調整** → **バックアップから復元**
（最新の検証済みバックアップを復元します）

### 安全性

- 復元前に必ず SHA-256 を再検証します。検証に失敗したバックアップは**適用されません**。
- 復元はファイル単位で不可分に置換されます。

### バックアップの保存先

既定: `<リポジトリ>/../aikensa_backups/<日時>_<理由>/`

```
20261120-150411_stage_a_verified/
  backup_manifest.json      ← 元パス・SHA-256・サイズ
  cam/cam_id.yaml
  cam/cam_config.yaml
  camera/Calibration_camera_0.yaml
  ...
  adjustments/global_alignment.yaml
```

**リポジトリの外**に保存されるため、`git pull` や `git clean` で消えることはありません。
